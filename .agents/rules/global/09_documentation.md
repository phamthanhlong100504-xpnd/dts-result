# Documentation

## Purpose

Define mandatory documentation standards.

---

## Scope

Applies to all repositories, services, APIs, infrastructure, and libraries.

---

## Principles

- Accurate
- Up-to-date
- Discoverable
- Minimal
- Actionable

---

# Rules

## MUST

### DOC-001

Every repository MUST contain a README.

### DOC-002

Every public API MUST be documented.

### DOC-003

Every configuration option MUST be documented.

### DOC-004

Document architectural decisions.

### DOC-005

Keep documentation synchronized with implementation.

### DOC-006

Document deployment requirements.

### DOC-007

Document environment variables.

### DOC-008

Document breaking changes.

### DOC-009

Document external dependencies.

### DOC-010

Document build instructions.

### DOC-011

Document test instructions.

### DOC-012

Document local development setup.

### DOC-013

Document operational procedures.

### DOC-014

Document security assumptions.

### DOC-015

Document version compatibility.

---

## MUST NOT

### DOC-016

Do not keep obsolete documentation.

### DOC-017

Do not duplicate documentation.

### DOC-018

Do not document implementation details unnecessarily.

### DOC-019

Do not leave TODO documentation in production.

### DOC-020

Do not rely solely on source code as documentation.

---

## SHOULD

### DOC-021

Use diagrams for architecture.

### DOC-022

Use examples.

### DOC-023

Keep documentation concise.

### DOC-024

Organize documentation consistently.

### DOC-025

Prefer Markdown.

---

## MAY

### DOC-026

Generate API documentation automatically.

### DOC-027

Generate database documentation automatically.

---

# Minimum Repository Documentation

- README
- Architecture
- Development Guide
- Deployment Guide
- Configuration
- API Documentation
- Changelog

---

# Anti-patterns

- Missing README
- Outdated Documentation
- Copy-Paste Documentation
- Undocumented API
- Hidden Configuration
- Broken Examples

---
